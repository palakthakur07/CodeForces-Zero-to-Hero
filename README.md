# 🚀 Codeforces Zero to Hero

> **From learning syntax → understanding patterns → building intuition → solving problems independently → becoming a strong competitive programmer.**

This repository is my personal **Codeforces + Competitive Programming learning system**.

It contains everything I learn throughout my journey — concepts, patterns, tricks, intuition, problem-solving approaches, mistakes, solutions, templates, contest notes, and important observations.

The goal is not just to collect solved problems.

The goal is to understand **how to think about problems**.

---

## 🎯 Goals

* Build strong problem-solving fundamentals.
* Develop competitive programming intuition.
* Learn common algorithms and data structures.
* Recognize patterns quickly.
* Understand multiple approaches to the same problem.
* Learn from wrong answers and failed approaches.
* Build reusable templates and tricks.
* Gradually solve higher-rated problems.
* Develop the ability to solve problems independently.
* Maintain a permanent revision resource.

---

## 🧠 How I Learn

For every new concept or problem, I try to focus on:

```text
Understand
   ↓
Observe
   ↓
Form an intuition
   ↓
Try an approach
   ↓
Find the problem with the approach
   ↓
Discover the key idea
   ↓

   ↓

   ↓

```

The objective is to remember the **reasoning**, not just the code.

## 🔄 Revision System

Revision should focus on **active recall**, not simply rereading.

For important problems, ask:

* Can I explain the idea without looking?
* Can I identify the pattern?
* Can I derive the solution again?
* Can I implement it without copying?
* Do I remember the complexity?
* Do I remember the common traps?

If the answer is no, the problem still needs revision.

## 📌 Core Philosophy

### Don't memorize solutions. Understand patterns.

A single problem is useful.

Understanding why that problem works is more useful.

Recognizing the same idea in a completely different problem is even more useful.

---

### Don't hide mistakes.

Wrong answers, TLEs, failed approaches, and bugs are part of the learning record.

They show how my problem-solving ability evolves.

---

### Don't chase problem counts.

100 problems deeply understood can be more valuable than 500 problems solved by memorizing patterns.

The goal is **understanding over quantity**.

---

### Always ask "Why?"

Instead of only asking:

> "What is the solution?"

Ask:

> "Why does this solution work?"

> "Why does this observation matter?"

> "Why does the brute force fail?"

> "Why is this data structure appropriate?"

> "Why is this complexity sufficient?"
